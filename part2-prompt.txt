기존 「파도의 사이」 1부의 HTML·CSS·JavaScript와 사진 폴더, 「10332 허민서 2학기 철수세미 탐구 보고서.hwpx」, Chujado_Wave_Lab_v2_CFD.zip을 함께 첨부한다.

[전체 제작 프롬프트]

첨부한 보고서와 파이썬 프로그램을 읽고 기존 1부에 이어지는 2부 인터랙티브 과학 잡지를 만들어 줘. 초등 고학년부터 중학교 1학년까지 이해할 수 있는 한국어로 설명하고, 직접 조작할 수 있는 웹사이트로 완성해 줘.

1. 첫 화면과 연결
접속하면 바로 1부와 2부를 선택하게 해 줘. 1부는 ‘작은 수조에서 시작된 질문’, 2부는 ‘파도 에너지의 행방을 찾아서’처럼 탐구의 연결이 보이게 제목을 붙여 줘. 1부의 기존 사진과 기능을 보존하고, 양쪽에서 선택 화면으로 돌아가거나 다른 부로 이동할 수 있게 해 줘. 기존 1부 페이지 내 바로가기 주소도 가능한 한 보존해 줘.

2. 눈높이와 내용
긴 문장을 짧게 나누고 한 문단에는 한 가지 핵심만 써 줘. 파고는 파도 마루와 골의 높이 차이, 주기는 한 지점에 다음 마루가 오는 시간, 반사는 되돌아가는 에너지, 투과는 뒤로 전해지는 에너지, 공극률은 전체 공간 중 빈틈의 비율로 설명해 줘.
소산은 에너지가 없어지는 것이 아니라 마찰과 복잡한 흐름 등을 거쳐 다른 형태로 바뀌는 것이라고 설명해 줘. 모델이 계산한 몫은 ‘모델 소산’으로 표시해 줘.
복잡한 식, 등가 다공층, 복소수, 와도 등의 설명은 접을 수 있는 ‘더 알아보기’에 넣어 줘. 질문과 관찰로 배우게 하되 지나치게 유아적인 말투는 피하고 짧고 친절하게 써 줘.

3. 출처 확인과 과학적 정확성
보고서와 원본 코드, 자료 출처 기록, 검증 기록을 직접 확인해 줘. 1부의 실제 수조 관찰, 2부의 빠른 파이썬 모델, 별도의 3차원 유동 계산을 구분해 줘. 계산값을 실제 바다의 측정 성능처럼 쓰지 마.
추자도 대표 조건은 낮은 파도 0.4 m·4.3초, 보통 파도 1.1 m·4.9초, 높은 파도 2.0 m·6.4초야. 실제 자료를 확인해 사용해 줘. P10·P90은 분포 경계값이지 파도의 10%·90% 크기라는 뜻이 아니야. 세 조건은 파고와 주기가 함께 바뀌므로 차이를 파고만의 효과라고 결론 내리지 마.
원본 model.py를 실행하여 세 대표 파도에서 공극률 25~80%를 1퍼센트포인트 간격으로 계산한 표를 웹 체험에 사용해 줘. 계산이 불가능하면 보고서에서 확인한 조건만 선택하게 제한해 줘. 임의의 숫자나 보간값을 원본 계산처럼 쓰지 마.
수심 10 m, 층 두께 14 m, 대표 크기 2 m 등 원본의 가정을 적고 에너지 비율 합 R+T+D=100%를 확인해 줘. 실제 적층 모양을 재현하거나 실험에 맞춰 검증한 설계 도구가 아니라는 점을 밝혀 줘.

4. 체험 1 — 파도 리듬 맞추기
낮은·보통·높은 파도 버튼을 누르면 설명용 물결의 높이와 주기가 달라지게 해 줘. 파고와 주기를 숫자와 쉬운 문장으로 함께 설명해 줘. 한 지점의 오르내림을 표시하고 멈추기·재생 버튼을 넣어 줘. 파장을 고정한 설명용 애니메이션이고 실제 유동 계산 영상은 아님을 표시해 줘.

5. 체험 2 — 파도 에너지 배달소
들어온 파도 에너지를 100칸으로 표현해 줘. 한 칸은 에너지 약 1%이며 물 입자나 블록 개수가 아님을 설명해 줘.
‘아무것도 놓지 않기’, ‘틈 없는 이상 반사벽’, ‘빈틈 있는 층’을 선택하게 해 줘. 원본 모델의 이상 조건에서 구조물이 없으면 투과 100%, 완전 반사벽이면 반사 100%로 표시해 줘. 실제 모든 벽이 완전 반사한다는 뜻은 아니야.
파도 조건과 빈틈 비율 슬라이더를 넣고, 다공층을 선택했을 때만 슬라이더를 활성화해 줘.
반사·투과·모델 소산을 색과 글자로 구분해 줘. ‘에너지 보내기’를 누르면 설명용 점들이 세 갈래로 움직이게 해 줘. 이것은 실제 파도나 와류를 계산하는 장면이 아니라 에너지 비율을 설명하는 장면이야.
칸 수를 반올림할 때 합이 항상 100칸이 되게 하고, 정확한 비율은 소수점 둘째 자리까지 표시해 줘. 숫자는 파도 높이 비율이 아니라 에너지 비율임을 알려 줘.
‘이 조건 기억하기’와 ‘기록 지우기’, ‘처음 조건으로’를 넣어 줘. 최대 6개 조건을 표로 비교하고 새로고침하면 기록이 사라짐을 알려 줘. 공정한 비교는 다른 조건을 같게 하고 한 가지만 바꾸는 것이라고 설명해 줘.

6. 두 가지 미션
보통 파도에서 공극률 25%, 35%, 80% 중 하나를 고르는 미션 두 개를 만들어 줘.
A: 어느 조건의 투과가 가장 작은가?
B: 어느 조건의 모델 소산이 가장 큰가?
보고서의 비교값:
25%: 반사 37.07%, 투과 7.06%, 모델 소산 55.87%.
35%: 반사 19.70%, 투과 19.75%, 모델 소산 60.55%.
80%: 반사 1.72%, 투과 85.31%, 모델 소산 12.97%.
틀려도 다시 시도할 수 있게 하고, 선택하면 세 조건을 숫자로 함께 비교해 줘. ‘통과가 작다’와 ‘소산이 크다’는 다른 목표라는 것을 발견하게 해 줘. 35%는 세 선택지에서 소산이 가장 큰 값이지 실제 바다의 최적 공극률이 아니야.

7. 프로그램 제작 과정
말로 요청하기, 실행하기, 조건과 오류를 확인하고 고치기로 AI 도움을 받아 프로그램을 만든 과정을 설명해 줘. 학생이 설명할 수 있는 짧은 코드 예를 넣어 줘. 예를 들어 이름으로 파고·주기를 찾는 사전과 ‘모델 소산 = 100 - 반사 - 투과’의 관계를 설명해 줘. 예시 코드와 실제 전체 계산 코드는 구분해 줘.
화면이 나온다고 계산의 정확성이 보장되는 것은 아니며 단위와 가정과 검증을 사람이 확인해야 한다고 설명해 줘.
약 20.45초에서 시간 간격이 매우 작아진 초기 계산 사례도 적어 줘. 중단 기능은 오류 감지이지 불안정 문제의 해결 자체가 아님을 밝혀 줘.

8. 보고서의 실제 탐구 이미지
보고서 안의 실제 프로그램 화면을 추출해서 관련 설명 옆에 배치해 줘. 세 구조물 에너지 비교, 공극률 비교 그래프, 입체 수면 화면, 3차원 유동 화면을 적절히 사용해 줘. 이미지를 누르면 확대되고 각 화면의 의미를 쉬운 캡션으로 읽을 수 있게 해 줘. 존재하지 않는 실험 사진이나 결과를 생성하지 말고 원본의 수치와 축을 왜곡하지 마. 불필요한 계정 정보가 있는 화면은 제외해 줘.

9. 입체 표시와 3차원 계산
‘입체 수면 화면’과 ‘3차원 유동 계산 화면’을 버튼으로 전환해 비교하게 해 줘. 입체로 돌려 보는 화면이 구조물 주변 3차원 와류를 직접 계산했다는 뜻은 아니라고 설명해 줘.
CFD는 공간을 작은 칸으로 나눠 물의 움직임을 계산하는 방법이라고 설명해 줘. 원본의 OpenFOAM 거친 격자 80초 예제는 입력 파고와 계산에서 측정한 파고가 크게 달랐고 추가 검증이 부족하므로 실제 성능이나 와류의 정확한 소산 기여도를 확정하지 마.

10. 체험 3 — 회전 탐정
나란히 흐르는 화살표와 빙글빙글 도는 설명용 흐름을 고르게 해 줘. 작은 바람개비를 드래그하거나 방향키로 옮겨 회전 성질을 살펴보게 해 줘.
같은 방향·같은 빠르기의 흐름에서는 돌지 않고, 회전성이 강한 중심 근처에서는 더 빠르게 도는 개념 모형을 만들어 줘. 멈추기·재생과 관찰 위치에 맞는 쉬운 설명을 넣어 줘.
실제 물 실험이나 CFD 결과가 아니며 실제 발전기 회전수·발전량을 뜻하지 않음을 명확히 표시해 줘. 회전하는 흐름을 관찰했다고 소산 비율까지 안 것은 아니라는 설명으로 마무리해 줘.

11. 퀴즈와 다음 탐구
마지막에 세 가지 개념을 확인하는 퀴즈를 넣어 줘.
- 뒤쪽 파도가 없다고 모두 소산한 것은 아니다.
- 빈틈의 영향만 보려면 파도와 다른 조건을 같게 한다.
- 입체 화면과 3차원 유동 계산은 다르다.

12. 디자인·접근성·검증
기존 잡지 분위기를 이어 가며 2부는 남색·연보라·민트로 구분해 줘. 큰 제목과 충분한 여백, 짧은 문단, 실제 이미지 캡션, 접어 두는 추가 설명을 사용해 줘.
휴대폰에서 읽고 누르기 쉬운 크기로 만들고 가로 넘침이 없게 해 줘. 색뿐 아니라 글자와 숫자로 결과를 구분하고, 키보드 조작·초점 표시·대체 글·움직임 줄이기 설정을 지원해 줘.
전체 프롬프트를 잡지 안에서 열어 보고 복사하거나 텍스트로 받을 수 있게 해 줘.
첫 화면, 1·2부 이동, 슬라이더, 기록 표, 미션, 이미지 확대, 회전 체험, 퀴즈, 모바일 구성을 확인한 뒤 기존 사이트에 반영해 줘. 확인하지 못한 사항은 확인했다고 말하지 마.
